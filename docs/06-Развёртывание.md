# Развёртывание, эксплуатация и тестирование

## 1. Состав поставки

| Компонент | Проект | Назначение |
|-----------|--------|-----------|
| Сервер приложений | `src/FinFlow.Api` | REST API, веб-клиент аналитики, Swagger |
| Операционный клиент | `src/FinFlow.Desktop` | WPF-приложение (Windows) |
| Библиотеки | `Domain`, `Contracts`, `Application`, `Infrastructure` | бизнес-логика и доступ к данным |
| Тесты | `tests/FinFlow.Tests` | контрольные расчёты и правила |

## 2. Требования к среде

- .NET SDK 8.0 (для сборки) или .NET Runtime 8.0 + ASP.NET Core Runtime 8.0
  (для запуска сервера).
- SQL Server 2019 и новее, либо SQL Server LocalDB, либо Azure SQL.
- Windows 10/11 с .NET Desktop Runtime 8.0 — для WPF-клиента.
- Для эксплуатации: TLS-сертификат, резервное копирование, мониторинг.

## 3. Настройка подключения

`src/FinFlow.Api/appsettings.json`:

```json
{
  "ConnectionStrings": {
    "Default": "Server=localhost;Database=FinFlow;User Id=finflow;Password=***;TrustServerCertificate=True;MultipleActiveResultSets=true"
  }
}
```

Допустимые переопределения:

- `ConnectionStrings__Default` — переменная окружения (рекомендуется для
  промышленной среды);
- `FINFLOW_CONNECTION` — используется фабрикой `BankDbContextFactory`
  при выполнении команд `dotnet ef`.

## 4. Сборка и запуск

```bash
dotnet restore FinFlow.sln
dotnet build FinFlow.sln -c Release
dotnet run --project src/FinFlow.Api -c Release     # http://localhost:5080
```

Порт задан в `src/FinFlow.Api/Properties/launchSettings.json`; в IIS/Kestrel
он настраивается привязкой (`ASPNETCORE_URLS`).

WPF-клиент:

```powershell
$env:FINFLOW_API = "https://finflow.bank.local"
dotnet run --project src/FinFlow.Desktop -c Release
```

Если переменная не задана, используется `http://localhost:5080`.

## 5. Создание и заполнение базы

При старте сервер вызывает `InitializeDatabaseAsync`:

1. `Database.EnsureCreatedAsync()` — создание схемы по модели EF Core;
2. `DbSeeder.SeedAsync` — идемпотентное заполнение:
   роли, 8 пользователей, параметры, продукты и версии, клиенты, счета и
   договоры, демонстрационные операции, реестр рисков, прогноз ликвидности.

Если строка подключения недоступна, сервер продолжает работу, а в журнал
пишется предупреждение — это позволяет открыть Swagger и веб-клиент.

Для перехода на миграции:

```bash
dotnet ef migrations add Initial --project src/FinFlow.Infrastructure \
  --startup-project src/FinFlow.Api
dotnet ef database update --project src/FinFlow.Infrastructure \
  --startup-project src/FinFlow.Api
```

## 6. Тестирование

```bash
dotnet test
```

Проверяются:

- формулы (1.1), (1.2), (1.5)–(1.10) — точные значения из записки;
- горизонт ликвидности таблицы 1.5 (разрыв 2 500 тыс. р. на третий день);
- стоимость ресурсов и маржа (7,725 %, 2 220, 241 тыс. р.);
- риски: EMV 1 330, σ 772,6, резерв 1 979, перечень R ≥ 10;
- маршрутизация операций по лимитам и признакам ПОД/ФТ;
- длина прежнего и изменённого номера счёта, дата перехода 01.01.2027;
- календарное правило «31 января + 1 месяц = 28 февраля».

Ручная проверка API — `docs/05-API.md`, Swagger, веб-клиент.

## 7. Эксплуатационные настройки

| Параметр | Где задаётся | Значение по умолчанию |
|----------|--------------|----------------------|
| Строка подключения | `appsettings.json`, переменная окружения | LocalDB, база `FinFlow` |
| Адрес API для WPF | `FINFLOW_API` | `http://localhost:5080` |
| Время жизни токена | `InMemoryTokenStore` | 15 минут |
| Лимит операциониста | параметр `OperatorLimit` / `ModelBankData` | 5 000 р. |
| Лимит контролёра | параметр `ControllerLimit` | 50 000 р. |
| Порог ПОД/ФТ | параметр `AmlThreshold` | 20 000 р. |
| Горизонт прогноза | запрос `days`, максимум 365 (в режиме БД — 90) | 30 дней |
| Ставка налога | параметр `TaxRate` | 13 % |
| Ставка до востребования | параметр `DemandRate` | 0,1 % |

Значения параметров изменяются администратором на вкладке
«Администрирование» либо через `POST /api/parameters`; каждое изменение
создаёт новую запись с датой действия.

## 8. Требования промышленной эксплуатации

- TLS 1.2+ на всех внешних соединениях, HSTS, запрет слабых шифров.
- Резервное копирование SQL Server: RPO 5 минут (журнал транзакций),
  RTO 1 час; ежегодная проверка восстановления.
- Доступность 99,9 % — кластер/SQL Server Always On, два экземпляра API
  за балансировщиком.
- Журнал аудита хранится не менее 5 лет, запись только добавляется;
  выгрузка в архив выполняется регламентно.
- Мониторинг: `/api/health`, счётчики ошибок ProblemDetails, длительность
  закрытия дня, размер очереди контроля и очереди ПОД/ФТ.
- Для реальной ЭЦП подключается внешний криптопровайдер (в учебной версии
  подпись имитируется строковым отпечатком).
- Интеграции АИС ИДО, главной книги и МСИ заменяются адаптерами,
  реализующими `IAisIdoGateway`, `ILedgerGateway`, `IMsiGateway`.

## 9. Диагностика

| Симптом | Причина | Решение |
|---------|---------|---------|
| `dotnet` не найден | не установлен SDK | установить .NET SDK 8.0 |
| `База данных не подготовлена` в журнале | недоступен SQL Server | проверить строку подключения, запустить службу |
| WPF: «Сервер недоступен» | другой порт или сервер не запущен | задать `FINFLOW_API`, запустить API |
| 401 при работе клиента | истёк 15-минутный токен | повторный вход |
| 409 «Изменился доступный остаток» | параллельное списание или новое ограничение | проверить остаток, повторить операцию |
| 403 «Автор не может подтвердить свою операцию» | нарушено бизнес-правило 12 | подтверждение другим сотрудником |
| Операция не появляется в очереди ПОД/ФТ | сумма ниже порога и риск клиента не повышен | проверить параметры и анкету |

## 10. Ограничения учебной версии

- Хранилище токенов — в памяти процесса: при перезапуске API сеансы
  завершаются, при нескольких экземплярах требуется распределённое хранилище.
- Уведомления, отчёты в XLSX/PDF, интерфейс ДБО, реальная ЭЦП и адаптивный
  доступ для руководителя реализованы в сокращённом виде (п. 1.11 записки).
- Монте-Карло для оценки рисков не применяется: используется нормальное
  приближение квантиля P80 (`P80ReserveStrategy`).
- Юридически значимый документооборот и регуляторная отчётность вне границ
  разработки.
