# Требования к системе

## 1. Границы разработки

В системе реализуются только процессы, связанные с клиентами, счетами и вкладами:

**Входит в разработку:** клиенты и их идентификация; текущие счета и вклады;
договоры и версии условий; кассовые и безналичные операции; доступный остаток;
ограничения по счёту; начисление, капитализация и выплата процентов; налог с
процентов; досрочный возврат; закрытие операционного дня; отчётность
руководителя; администрирование пользователей и журнал аудита; личный кабинет
клиента.

**Не входит (удалено из системы):** реестр и оценка рисков, резервы, прогноз
ликвидности и разрывов, маржинальный анализ, ПОД/ФТ-контроль и анкеты,
представители клиентов, интеграции с АИС ИДО, МСИ и главной книгой,
продуктовый конструктор с контролем РВСР, аналитическая панель.

## 2. Роли

| Роль | Рабочее место | Задачи |
|------|---------------|--------|
| Сотрудник банка | WPF | Ведение клиентов, открытие и закрытие счетов, оформление вкладов, операции, закрытие дня |
| Администратор | WPF | Учётные записи сотрудников, блокировка, журнал аудита, просмотр отчёта |
| Руководитель | WPF | Просмотр отчёта о работе сотрудников за период |
| Клиент банка | веб | Просмотр своих вкладов, сроков и условий |

Ролей контролёра, бухгалтера, казначея, риск-менеджера и специалиста ПОД/ФТ
в системе нет.

## 3. Функциональные требования

### 3.1. Клиенты

- **ФТ-1.** Регистрация клиента типов «физическое лицо», «юридическое лицо»,
  «индивидуальный предприниматель» с уникальным идентификационным номером.
- **ФТ-2.** Статус идентификации; операции и открытие счёта доступны только
  идентифицированному клиенту. Вновь зарегистрированный клиент идентифицируется
  сразу.
- **ФТ-3.** Поиск по наименованию и номеру документа с постраничной выдачей,
  карточка клиента со счетами и вкладами.
- **ФТ-4.** Изменение контактных данных и подтверждение идентификации.
- **ФТ-5.** Для физического лица обязательна дата рождения — она используется
  как контрольный реквизит входа в личный кабинет.

### 3.2. Счета и ограничения

- **ФТ-6.** Открытие текущего счёта по продукту с утверждённой версией условий.
- **ФТ-7.** Два номера счёта: прежний (13 знаков) и изменённый (17 знаков,
  действует с 01.01.2027); поиск по любому из них.
- **ФТ-8.** Доступный остаток `D = max(0; B + L − H)`; при аресте `L = 0`.
- **ФТ-9.** Лимит овердрафта задаётся и изменяется сотрудником.
- **ФТ-10.** Ограничения (арест, бронирование, авторизационная блокировка)
  уменьшают доступный остаток; снятие ограничения возвращает сумму.
- **ФТ-11.** Закрытие счёта возможно при нулевом доступном остатке и отсутствии
  ареста; закрытие счёта закрывает связанные договоры.

### 3.3. Вклады и договоры

- **ФТ-12.** Продукт имеет версии условий; договор ссылается на версию,
  действовавшую на дату открытия, и не меняется при появлении новых версий.
- **ФТ-13.** Минимальная сумма вклада проверяется при открытии.
- **ФТ-14.** Досрочный возврат отзывного вклада выполняется с перерасчётом по
  ставке до востребования; безотзывного — только после согласия банка.
- **ФТ-15.** Пролонгация вклада при наступлении срока, если она разрешена
  условиями; иначе вклад возвращается и счёт закрывается.
- **ФТ-16.** Просмотр начислений по договору.

### 3.4. Операции

- **ФТ-17.** Ручное проведение операций: взнос наличными, безналичное
  поступление, выдача наличными, безналичное списание, частичное снятие,
  досрочный возврат.
- **ФТ-18.** Проверка доступного остатка до исполнения; при недостатке средств
  операция отклоняется с указанием доступной и требуемой суммы.
- **ФТ-19.** Исполнение операции и изменение остатка выполняются в одной
  транзакции; параллельные операции не выводят счёт в недопустимый остаток.
- **ФТ-20.** Исполненная операция не изменяется: сторнирование создаёт обратную
  операцию и помечает исходную как сторнированную. Системные операции
  (проценты, налог, капитализация) и досрочный возврат не сторнируются.
- **ФТ-21.** Сторнирование доступно только для исполненной и ещё не
  сторнированной операции.

### 3.5. Проценты, налог, закрытие дня

- **ФТ-22.** Ежедневное начисление процентов по фактическому числу дней и
  ставке дня по формуле (1.5); повторный запуск не создаёт дублей.
- **ФТ-23.** Ежемесячная капитализация или выплата процентов согласно условиям;
  выплата в конце срока.
- **ФТ-24.** Удержание подоходного налога с процентов по формуле (1.8) с учётом
  освобождения для вкладов в BYN от 1 года и в валюте от 2 лет.
- **ФТ-25.** Закрытие операционного дня с фиксацией этапов и итогов; повторный
  запуск продолжает обработку, а не повторяет начисления.

### 3.6. Отчётность

- **ФТ-26.** Отчёт о работе сотрудников за период: клиенты, счета, вклады и их
  суммы, количество операций и оборот, закрытия дня; итоги по отделению.
- **ФТ-27.** Отчёт доступен руководителю и администратору, содержит выбранный
  период и дату формирования.

### 3.7. Администрирование и безопасность

- **ФТ-28.** Создание учётных записей сотрудников с ролью, пароль не короче
  12 символов, уникальный логин.
- **ФТ-29.** Блокировка и разблокировка учётной записи; блокировка после пяти
  неудачных попыток входа.
- **ФТ-30.** Журнал аудита действий; доступен администратору.
- **ФТ-31.** Личный кабинет клиента: вход по документу и дате рождения, просмотр
  только своих данных.

## 4. Бизнес-правила

1. Операции и открытие счёта — только идентифицированному клиенту.
2. Договор фиксирует версию условий продукта.
3. Изменение условий продукта оформляется новой версией.
4. Недостаточно средств — операция отклоняется, остаток не меняется.
5. Исполненная операция не редактируется и не удаляется.
6. Сумма действующих ограничений уменьшает доступный остаток.
7. При аресте овердрафт не применяется.
8. Досрочный возврат безотзывного вклада — только с согласия банка.
9. Неснижаемый остаток вклада не может быть нарушен расходной операцией.
10. Проценты выплачиваются или капитализируются по условиям версии.
11. Налог удерживается банком как налоговым агентом.
12. Закрытие дня идемпотентно по этапам и начислениям.

## 5. Нефункциональные требования

- **НФТ-1.** Стек .NET 10, C# 14, ASP.NET Core, EF Core 10, SQL Server.
- **НФТ-2.** Слоистая архитектура, зависимости направлены внутрь.
- **НФТ-3.** Все суммы — `decimal(18,4)`, ставки — `decimal(9,6)`, деньги
  округляются единообразно (`Money.Round`).
- **НФТ-4.** Оптимистическая блокировка изменяемых сущностей (`RowVersion`).
- **НФТ-5.** Аутентификация по токену; пароли хранятся в виде хеша.
- **НФТ-6.** Журнал аудита — только добавление записей.
- **НФТ-7.** Сборка и тесты выполняются в GitHub Actions на `windows-latest`.
- **НФТ-8.** Документация API — Swagger UI по адресу `/swagger`.
- **НФТ-9.** WPF-клиент работает на Windows 10/11 с .NET Desktop Runtime 10.
