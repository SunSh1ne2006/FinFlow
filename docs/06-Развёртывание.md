# Развёртывание, эксплуатация и тестирование

## 1. Состав поставки

| Компонент | Проект | Назначение |
|-----------|--------|-----------|
| Сервер приложений | `src/FinFlow.Api` | REST API, Swagger, личный кабинет клиента `/client/` |
| Рабочее место сотрудника | `src/FinFlow.Desktop` | WPF-приложение (Windows): сотрудник, администратор, руководитель |
| Библиотеки | `Domain`, `Contracts`, `Application`, `Infrastructure` | бизнес-логика и доступ к данным |
| Тесты | `tests/FinFlow.Tests` | контрольные расчёты и свёртка отчёта |

## 2. Требования к среде

- .NET SDK 10.0 (сборка) или .NET Runtime 10.0 + ASP.NET Core Runtime 10.0
  (запуск сервера). Целевые платформы: `net10.0`, WPF — `net10.0-windows`.
- Пакеты: EF Core 10.0, Swashbuckle.AspNetCore 10.3 (OpenAPI 2.7), xUnit v3 с
  Microsoft Testing Platform (`global.json`).
- SQL Server 2019 или новее, SQL Server LocalDB либо Azure SQL.
- Windows 10/11 с .NET Desktop Runtime 10.0 — для WPF-клиента.

## 3. Настройка подключения

`src/FinFlow.Api/appsettings.json`:

```json
{
  "ConnectionStrings": {
    "Default": "Server=(localdb)\\MSSQLLocalDB;Database=FinFlow;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True"
  }
}
```

Переопределения:

- `ConnectionStrings__Default` — переменная окружения для сервера;
- `FINFLOW_CONNECTION` — используется `BankDbContextFactory` при командах
  `dotnet ef`.

## 4. Сборка и запуск

```bash
dotnet restore FinFlow.sln
dotnet build FinFlow.sln -c Release
dotnet run --project src/FinFlow.Api -c Release      # http://localhost:5080
```

- корень `/` перенаправляет в личный кабинет `/client/`;
- Swagger: `http://localhost:5080/swagger`;
- состояние сервера: `http://localhost:5080/api/health`.

Порт задан в `src/FinFlow.Api/Properties/launchSettings.json`; в IIS/Kestrel
настраивается привязкой (`ASPNETCORE_URLS`).

WPF-клиент:

```powershell
$env:FINFLOW_API = "https://finflow.bank.local"
dotnet run --project src/FinFlow.Desktop -c Release
```

Если переменная не задана, используется `http://localhost:5080`.

### 4.1. Ошибка NETSDK1005

```
файл ресурсов "...\obj\project.assets.json" не содержит целевого объекта для "net10.0-windows"
```

Ошибка означает, что в папке `obj` лежит файл восстановления от другой версии
проекта (прежняя целевая платформа, другой компьютер или другой SDK). Сборка не
пересоздаёт его автоматически, поэтому нужно удалить артефакты и повторить
восстановление:

```powershell
Get-ChildItem -Path . -Directory -Recurse -Force |
    Where-Object { $_.Name -in @('obj', 'bin') } |
    Remove-Item -Recurse -Force
dotnet restore FinFlow.sln
dotnet build FinFlow.sln
```

То же самое делает `scripts/clean.ps1`. В Visual Studio: **Сборка → Очистить
решение**, затем **Сборка → Восстановить пакеты NuGet** и пересборка.

### 4.2. Сквозная проверка работоспособности

```powershell
powershell -File scripts/smoke.ps1 -StartApi
```

Скрипт запускает API на `http://localhost:5080`, создаёт тестового клиента и вклад
и проверяет: вход сотрудника, открытие вклада, взнос, отклонение операции при
недостатке средств, сторнирование, расчёт и исполнение досрочного возврата,
закрытие операционного дня с начислениями, отчёт руководителя, пользователей и
журнал аудита, вход в личный кабинет клиента. Результат — в `smoke.log`, код
возврата `0` при успехе. В CI это отдельное задание `smoke`.

## 5. Создание и заполнение базы

При старте сервер вызывает `InitializeDatabaseAsync`:

1. `Database.EnsureCreatedAsync()` — создание схемы по модели EF Core; затем
   схема сверяется с моделью (при расхождении демонстрационная база
   пересоздаётся) и проверяется колонка `Clients.BirthDate` (нужна личному
   кабинету).
2. `DbSeeder.SeedAsync` — идемпотентное заполнение:
   - три роли: сотрудник, администратор, руководитель;
   - демонстрационные учётные записи проверяются при каждом старте (наличие,
     пароль, роль);
   - сотрудники `employee1`, `employee2`, `admin`, `head`;
   - параметры: ставка налога 13 %, ставка до востребования 0,1 %,
     ставка рефинансирования 9,25 %;
   - продукты: текущий счёт «Удобный», вклады «Стабильный», «Свободный»,
     «Рост», «Долларовый»;
   - восемь клиентов, текущие счета и вклады, примеры ограничений;
   - демонстрационные операции за текущий день.

> **Важно.** Схема базы заметно сокращена по сравнению с прежними версиями
> (удалены риски, ликвидность, проводки, анкеты ПОД/ФТ, представители).
> `EnsureCreated` не изменяет существующую базу, поэтому при старте выполняется
> сверка схемы с моделью EF Core: если демонстрационная база создана прежней
> версией, она автоматически пересоздаётся вместе с начальными данными.
> Пароли демонстрационных учётных записей также проверяются при старте: если в
> базе остался хеш от прежней версии, он заменяется на `FinFlow#2026!`.

Если строка подключения недоступна, сервер продолжает работу, а в журнал
пишется предупреждение: Swagger и личный кабинет открываются, но данные
недоступны.

Переход на миграции:

```bash
dotnet ef migrations add Initial --project src/FinFlow.Infrastructure \
  --startup-project src/FinFlow.Api
```

## 7. Сборка и тесты в CI

`.github/workflows/build.yml` (GitHub Actions, `windows-latest`):

```yaml
- dotnet restore FinFlow.sln
- dotnet build FinFlow.sln -c Release --no-restore
- dotnet test --project tests/FinFlow.Tests/FinFlow.Tests.csproj -c Release
```

Локальный запуск тестов:

```bash
dotnet test --project tests/FinFlow.Tests/FinFlow.Tests.csproj -c Release
```

Покрыты: формулы (1.1)–(1.10), нумерация счетов, расчёт срока договора,
свёртка отчёта о работе сотрудников.

## 8. Эксплуатация

- Резервное копирование базы — штатными средствами SQL Server.
- Журнал аудита (`AuditLog`) хранится не менее 5 лет и только дополняется.
- Пароли сотрудников хранятся в виде хеша (PBKDF2), токены — в памяти процесса:
  после перезапуска сервера сотрудники и клиенты входят заново.
- Для промышленной среды: TLS-сертификат, ограничение CORS, внешний провайдер
  аутентификации, централизованный сбор журналов.

## 9. Типовые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| Вход отклонён: «Учётная запись заблокирована» | Пять неудачных попыток; администратор разблокирует в WPF |
| Демонстрационный сотрудник не входит с паролем `FinFlow#2026!` | Перезапустите сервер: при старте пароли демо-учёток восстанавливаются автоматически |
| Ошибка схемы после обновления | Перезапустите сервер: несовместимая демонстрационная база пересоздаётся автоматически |
| Клиент не входит в кабинет | Не идентифицирован, не физлицо или неверная дата рождения |
| Пустой отчёт руководителя | В периоде не было действий сотрудников или нет пользователей с ролью `Employee` |
| «Параметр не настроен на дату» | В `Parameters` нет значения с подходящей датой действия; пересоздайте базу |
| WPF не подключается | Не задан `FINFLOW_API`, сервер не запущен или порт занят |
