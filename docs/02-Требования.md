# Требования и трассировка реализации

Документ связывает требования пояснительной записки (таблицы 1.19–1.21, п. 1.11)
с классами, экранными формами и проверками. Границы MVP: требования **1–16, 19–21,
23, 24, 27**; требования 17, 18, 22, 25, 26 реализованы в сокращённом виде.

## 1. Функциональные требования (таблица 1.19 и 1.20 записки)

| № | Требование | Реализация | Проверка |
|---|-----------|------------|----------|
| 1 | Ведение клиентов: физлица, юрлица, ИП, представители, анкета ПОД/ФТ, данные МСИ | `ClientService`, `Client`, `Representative`, `KycProfile`, `ClientsController`; экран «Клиенты» WPF | Операция без идентифицированного клиента отклоняется (`OperationService.CreateAsync`); актуальность анкеты видна в карточке |
| 2 | Продуктовый конструктор: вид по Декрету № 7, валюта, срок, ставка, капитализация, пролонгация, неснижаемый остаток; версии условий | `Product`, `ProductVersion`, `ProductService` (создание версии, утверждение, контроль РВСР) | Изменение условий создаёт новую версию; договор ссылается на конкретную версию |
| 3 | Открытие и закрытие счетов по Плану счетов № 126 с прежним и изменённым номером | `Account`, `AccountNumber`, `AccountNumberGenerator`, `AccountService` | `AccountNumberGenerator.Build` даёт 13 и 17 знаков; поиск по номеру — `GET /api/accounts/lookup` |
| 4 | Договоры вклада и текущего счёта, дополнительные соглашения, доверенности | `Contract`, `ContractService`, `ContractsController` | Договор связан с продуктом, версией и счётом; согласие банка на досрочный возврат (`POST /api/contracts/{id}/consent`) |
| 5 | Доступный остаток по формуле (1.1) с учётом овердрафта и ограничений | `BalanceCalculator.Available`, `BalanceService` | Тест `Available_balance_matches_formula_1_1` (14 000 / 3 000 / 0) |
| 6 | Ограничения: аресты, приостановления, бронирования с основанием и сроком | `Hold`, `HoldService`, `POST /api/accounts/{id}/holds` | При аресте `L = 0`; снятие ограничения пересчитывает `D` |
| 7 | Приходные и расходные операции: наличные, безналичные, частичное снятие, пополнение | `OperationService.CreateAsync/SubmitAsync`, `Operation` | Шаги таблицы 1.10: черновик → проверка условий → контроль → исполнение |
| 8 | Маршрут контроля, состояния операции, сторнирование | `WorkflowPolicy`, `OperationService`, таблица состояний | Тесты `WorkflowTests`; автор не может подтвердить свою операцию; сторно вместо изменения |
| 9 | Начисление процентов, капитализация, выплата (1.5)–(1.7) | `InterestCalculator`, `InterestService`, `InterestAccrual` | Тесты 97,67 р.; 10 290,26 р.; 12,13 % |
| 10 | Досрочный возврат с перерасчётом (1.9)–(1.10); безотзывный — только с согласия банка | `EarlyReturnCalculator`, `ContractService.QuoteEarlyReturnAsync`, `OperationKind.EarlyReturn` | Тест 147,95 / 1,64 / 146,31; отказ без согласия |
| 11 | Подоходный налог (1.8) по каждой сумме взноса | `TaxCalculator`, `TaxService`, `TaxWithholding` | Тест 12,70 р.; освобождение для BYN ≥ 365 дней и валюты ≥ 730 дней |
| 12 | Закрытие операционного дня: начисление, пролонгация, возврат, проводки, сверка | `DayCloseService`, `OperationalDay`, `Posting` | Повторный запуск не создаёт дублей `(ContractId, AccrualDate)`; сверка `ReconciliationDto` |
| 13 | Прогноз оттока, запаса и разрыва ликвидности на 90 дней (1.11)–(1.13) | `LiquidityCalculator`, `LiquidityService`, веб-экран «Ликвидность» | Тесты таблицы 1.5: разрыв 2 500 тыс. р. на третий день |
| 14 | Реестр рисков, EMV, σ, резерв P80, матрица 5×5, диаграмма «торнадо» | `RiskCalculator`, `RiskService`, `P80ReserveStrategy` | Тесты ΣEMV = 1 330; σ = 772,6; резерв 1 979; R ≥ 10 → R-01, R-02, R-04, R-10 |
| 15 | Средняя стоимость ресурсов и маржа (1.14)–(1.16) | `MarginCalculator`, `MarginService` | Тесты r̄ = 7,725 %; M = 2 220; П = 241 тыс. р. |

| 17 | Уведомления клиентам и сотрудникам (сокращённо) | `IEventPublisher` (`OperationChecked`, `OperationExecuted`, `DayClosed`, …) + журнал | События фиксируются в логе приложения; внешние каналы вне границ |
| 18 | Отчёты: портфель, остатки, проценты, налог, ликвидность, риски, реестр АГВ (сокращённо) | `ReportService` (`portfolio`, `portfolio.csv`, `agv`, `holds`, `tax`), `TaxService.ReportAsync` | Экран «Отчёты» веб-клиента; экспорт CSV |
| 19 | Журнал аудита и разграничение прав доступа | `AuditRecord`, `AuditService`, `IAuditWriter`, `[Authorize(Roles=…)]` | 8 ролей; каждая мутация пишет запись аудита; изменения журнала через API недоступны |
| 20 | Интеграция с АИС ИДО: приём ограничений и требований, квитанции | `IntegrationService.AcceptAisIdoDocumentAsync`, `AisIdoGateway`, `POST /api/integrations/ais-ido/documents` | Повторный `ExternalId` возвращает `Duplicate = true` и ссылку на первый документ |
| 21 | Обмен проводками с главной книгой, сверка оборотов | `Posting`, `LedgerGateway`, `IntegrationService.SyncLedgerAsync`, `POST /api/integrations/ledger/sync` | `ReconciliationDto.IsBalanced`, расхождение выводится в отчёте |
| 22 | Программный интерфейс для ДБО (сокращённо) | REST API с аутентификацией, `IdempotencyKey`, `DocumentSource.Dbo` | OpenAPI/Swagger, ответы ≤ 1 с на модельных данных |
| 23 | Контроль дублей: один документ исполняется один раз | `OperationDocument.ExternalId`, `Operation.IdempotencyKey`, проверка в `OperationService.CreateAsync` | Повторная отправка отклоняется; возвращается существующая операция/документ |
| 24 | Одновременная работа: атомарная повторная проверка остатка при списании | `IUnitOfWork` (транзакция), `SemaphoreSlim` в `OperationService`, `RowVersion` | Конфликт версий → HTTP 409; `D` не становится отрицательным |

| 26 | Адаптивный веб-доступ для руководителя (сокращённо) | Адаптивная вёрстка `wwwroot/css/app.css` (grid/flex, медиазапросы) | Отчёты доступны на узком экране |
| 27 | ПОД/ФТ-контроль: пороги, перечни, приостановление, формуляры | `WorkflowPolicy.HasAmlSigns`, `AmlService`, `AmlController`, экран «ПОД/ФТ» | Операция с признаками приостанавливается и попадает в очередь специалиста |

## 2. Бизнес-правила

| Правило | Формулировка | Место проверки |
|---------|--------------|----------------|
| 2, 3 | Условия вклада определяются версией продукта; действующие договоры сохраняют свою версию | `ProductService`, `Contract.ProductVersionId` |
| 4 | Операция по счёту невозможна без идентифицированного клиента | `OperationService.CreateAsync` |
| 5 | Расход невозможен, если сумма превышает доступный остаток (1.1) | `BalanceCalculator.CanDebit`, `OperationService` |
| 8 | Досрочный возврат безотзывного вклада — только с согласия банка (Декрет № 7) | `EarlyReturnCalculator`, `ContractService.QuoteEarlyReturnAsync` |
| 9 | Проценты начисляются по ставке версии, действующей в договоре | `InterestService`, `Contract.RatePercent` |
| 12 | Автор операции не может подтвердить её сам | `OperationService.ApproveAsync`, `Operation.CanBeApprovedBy` |
| 13 | Исполненная операция не изменяется — оформляется сторнирование с причиной | `OperationService.ReverseAsync` |
| 14 | К операции применяется значение параметра, действующее на её дату | `ParameterService.GetValueAsync` |

## 3. Переходы состояний операции

| Из | Событие | В |
|----|---------|---|
| Черновик | отправка, сумма ≤ 5 000 р., нет признаков ПОД/ФТ | Одобрена → Исполнена |
| Черновик | отправка, сумма > 5 000 р. | На контроле |
| Черновик | отправка, признаки ПОД/ФТ | Приостановлена |
| На контроле | подтверждение другим сотрудником | Одобрена → Исполнена → Отражена |
| На контроле | отклонение с причиной | Отказано |
| Приостановлена | решение ПОД/ФТ «одобрить» | Одобрена → Исполнена |
| Приостановлена | решение ПОД/ФТ «отклонить» | Отказано |
| Исполнена / Отражена | сторнирование с причиной | Сторнирована (+ обратная проводка) |

## 4. Нефункциональные требования (таблица 1.21)

| Категория | Требование | Реализация в учебном проекте |
|-----------|-----------|-------------------------------|
| СУБД | SQL Server, `decimal(18,4)` для сумм, `decimal(9,6)` для ставок | `BankDbContext.OnModelCreating` |
| Безопасность канала | TLS 1.2+ | Настраивается на IIS/Kestrel в эксплуатации |
| Аутентификация | Пароль + второй фактор для контролёра и администратора | `AuthService`, PBKDF2, токен 15 минут |
| Роли | 8 ролей | `RoleCode`, атрибуты `[Authorize]` |
| Производительность | 140 пользователей, 20 операций/с, p95 ≤ 2 с | Ограничение выборок, отсутствие N+1 в отчётах |
| Закрытие дня | ≤ 30 минут для 110 000 договоров | Пакетные выборки, проверка существующих начислений |
| Объём | 10 млн операций, 300 ГБ | Индексы по датам, счётам, статусам |
| Доступность | 99,9 %, RPO 5 минут, RTO 1 час | Резервное копирование и кластер — на уровне эксплуатации |
| Аудит | Хранение ≥ 5 лет, только добавление | `AuditRecord`, отсутствие операций изменения в API |
