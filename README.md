# FinFlow — сетевая система управления вкладами и текущими счетами банка

Учебный программный комплекс, разработанный по пояснительной записке
«Введение, главы 1 и 2 — Управление вкладами и текущими счетами банка».
Система автоматизирует операционный контур вкладов и текущих счетов коммерческого
банка Республики Беларусь и аналитический контур КУАП (ликвидность, стоимость
ресурсов, риски, ПОД/ФТ).

**Границы разработки — MVP по п. 1.11 записки:** функциональные требования
1–16, 19–21, 23, 24, 27. Требования 17, 18, 22, 25, 26 реализованы в сокращённом
виде (уведомления — внутрисистемные, отчёты — базовый набор с экспортом CSV,
ЭЦП — имитация подписи, интерфейс ДБО — REST API без отдельного клиента).

## Технологический стек

| Слой | Технология |
|------|-----------|
| Платформа | .NET 8 (C# 12) |
| Сервер приложений | ASP.NET Core 8 Web API, Swagger |
| Доступ к данным | Entity Framework Core 8, SQL Server (LocalDB для разработки) |
| Операционный клиент | WPF (MVVM), .NET 8 Windows |
| Аналитический клиент | SPA без внешних зависимостей (HTML/CSS/JS), раздаётся тем же сервером |
| Тесты | xUnit (контрольные примеры формул 1.1–1.20) |

## Структура решения

```
FinFlow.sln
├── src/
│   ├── FinFlow.Domain/          сущности, перечисления, расчётные классы, модельные данные
│   ├── FinFlow.Contracts/       DTO и запросы API (общие для сервера и клиентов)
│   ├── FinFlow.Application/     сервисы (Service Layer), абстракции, маппинг, бизнес-правила
│   ├── FinFlow.Infrastructure/  EF Core DbContext, Unit of Work, хеширование паролей,
│   │                            хранилище токенов, шлюзы интеграций, инициализация БД
│   ├── FinFlow.Api/             REST API, аутентификация, Swagger, веб-клиент аналитика
│   └── FinFlow.Desktop/         WPF-клиент операционного контура (MVVM)
├── tests/FinFlow.Tests/         проверочные расчёты и бизнес-правила
└── docs/                        архитектура, требования, расчёты, руководства, API
```

Зависимости направлены строго внутрь: `Api`/`Desktop` → `Infrastructure` → `Application`
→ `Domain`; `Contracts` используется сервером и клиентами. Домен не знает о EF Core
и ASP.NET Core.

## Быстрый старт

Требования: .NET SDK 8.0, SQL Server 2019+ или LocalDB, Windows для WPF-клиента.

```bash
# 1. Строка подключения (по умолчанию LocalDB)
#    src/FinFlow.Api/appsettings.json → ConnectionStrings:Default
#    либо переменная окружения ConnectionStrings__Default

# 2. Сборка и запуск сервера приложений
dotnet build FinFlow.sln
dotnet run --project src/FinFlow.Api      # http://localhost:5080

# 3. Аналитический веб-клиент
#    http://localhost:5080/  (Swagger: /swagger)

# 4. Операционный WPF-клиент
dotnet run --project src/FinFlow.Desktop  # обращается к http://localhost:5080
#    адрес переопределяется переменной окружения FINFLOW_API

# 5. Тесты
dotnet test
```

При первом запуске база создаётся (`EnsureCreated`) и заполняется демонстрационными
данными: роли, 8 пользователей, справочник параметров, продукты с версиями условий,
клиенты и счета, операции, 12 рисков, пятидневный горизонт ликвидности.

## Ограничения

- В границы разработки не входят карточный процессинг, кредитные продукты
  (кроме лимита овердрафта), полноценная главная книга, регуляторная отчётность,
  Монте-Карло, межбанковские расчёты и нативные мобильные приложения.
- Документ является учебным проектом: юридически значимая ЭЦП не применяется,
  подпись имитируется строковым отпечатком, интеграции реализованы шлюзами-заглушками
  с сохранением контрактов обмена.
- Исходный код подготовлен в среде без установленного .NET SDK: сборка и запуск
  выполняются на рабочей станции с .NET 8 и SQL Server.
